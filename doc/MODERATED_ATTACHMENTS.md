# Moderated forum and inbox attachments

LiXiangQi accepts staged uploads for inbox conversations and the four public discussion boards. The boards are Xiangqi Discussion, Game Analysis, LiXiangQi Feedback and Off-Topic. Existing age, account standing, posting rights, topic state, inbox preferences and blocking rules still apply. Team forums, blog discussions and diagnostic forums have no upload destination.

The chat gateway has no attachment write route. This includes tournament, player-to-player, spectator, study, team, simul, Swiss, broadcast, challenge, Three Kingdoms and other shared chat rooms. Xiangqi Kids uses curated avatar components and its existing account integration.

## Submission and storage

Approved photos appear inline in the inbox thread or forum post and expand on activation. A supported document appears as a download link. Its contents undergo malware and file-format checks and stay out of the photo detectors. Captions follow the same local text rules as other messages. The live chat text paths continue to use their existing moderation.

Inbox photos stay on the sender’s device while being edited. Send uploads the final selected photos and files for screening. An author can remove any staged item, including a failed one, and submit the rest. Retrying a check or approving a review enables a fresh Send or Post. The worker has no message or forum publishing operation. Authors see the third-party screening disclosure before selecting private media. The sender and the recipient can read a published private item through an authenticated application request. A Kid mark on either account prevents media in both directions. Each read resolves the actual visible parent and the current account state. Private URLs contain no bearer access grant. The app clears loaded previews when the account changes or the app backgrounds.

The server assigns a private random ID per upload, binds it to the author and the destination, hashes the original, and stores bounded bytes in `ugc_attachment`. The image encoder produces the only image representation readers can receive. Documents leave the server as explicit downloads with MIME sniffing disabled. Uploads carry the encoded filename in a request header to keep it out of access-log URLs. User-authored remote images render as links. The existing Picfit namespace also serves publicly addressable signed URLs and cannot enforce a changing inbox audience. The attachment service uses independent private storage. This release makes no destructive migration or visibility change to legacy Picfit objects. Changing access to those objects requires an inventory of published URLs, cache lifetimes, a recoverable backup and a separate migration.

The normal `push-local-live` Compose release requests both surfaces by default and checks the candidate scanner before stopping the live application. Local development defaults to uploads off. Explicit `UGC_FORUM=false` and `UGC_MSG=false` settings independently pause their surfaces and survive deployment. Pausing uploads preserves text and authorized reads. Existing installed mobile apps need a build that includes the composer.

Inbox messages accept up to eight attachments. Forum submissions accept four. Each upload can be up to 4 MiB and each author can start 20 uploads per hour. The server reads these values from `attachments.inboxMaxCount`, `attachments.maxCount`, `attachments.maxBytes` and `attachments.hourlyUploads`.

Inbox files can have any extension, including none. The worker recognizes raster photos from their bytes, removes metadata and emits WebP up to 2048 pixels on the longest side. The inbox also accepts bounded animations of up to 32 frames, screens every frame and caps total decoded pixels at 12 megapixels. Short private videos in supported MP4, QuickTime and WebM containers are re-encoded by FFmpeg as H.264 MP4 with optional AAC audio. The worker limits inline playback to 60 seconds and screens contact sheets covering every published frame. Links can include a sender-selected preview whose thumbnail uses this same private image screening and authorization. Other files, including archives and PDF documents, are malware-scanned and served as authenticated downloads. Text and PGN retain their format checks. Forum uploads accept single-frame JPEG, PNG and WebP, UTF-8 text and tagged PGN.

Inbox sends use the existing nonce and store a digest of the request, including reply, forward and ordered attachment IDs. Forum forms use an author/destination-bound nonce for creation and a content revision for editing. Media transactions verify the approved-byte digest and bind the parent revision together with the publication update. Inbox transactions also take a write lock on each participating account, including the source participant of a media forward. A concurrent Kid change conflicts with that write. An attachment ID alone cannot authorize a read. A forward receives its own ownership and destination record.

## Screening operations

The usual `push-local-live` deployment provisions the worker from the deployment user's `OPENAI_API_KEY` when no server credential exists. A dedicated override can be supplied in the website's ignored `data/local/secrets/attachment-worker.env` as one literal line, `UGC_OPENAI_KEY=<key>`. The release transfers credentials separately from application assets. It preserves an existing server key and rejects a conflicting explicit file. The deployment manages ClamAV, its private socket and signatures, and an isolated Mongo evidence volume accessible only to the scanner network. Allow at least 3 GiB of RAM for antivirus in addition to the site's normal requirements. [ClamAV container sizing](https://docs.clamav.net/manual/Installing/Docker.html)

Before stopping the site, the candidate worker checks the Mongo replica set, restricted vault, antivirus and OpenAI using a synthetic image. Stalled or unhealthy screening uses the site's existing moderator monitor. Restricted cases create a critical communications report with an opaque case ID. Keep restricted evidence and backups accessible only to designated responders.

After malware and format checks the worker sends only normalized photo pixels to `omni-moderation-latest`. A flagged result blocks publication. The scanner records the pipeline revision, returned model and categories. Timeouts and invalid responses leave the draft unavailable. Known or suspected material held for restricted handling stays outside the general endpoint. The general image model provides no dedicated child sexual abuse classification. [OpenAI moderation guide](https://developers.openai.com/api/docs/guides/moderation)

MongoDB leases survive restarts. A worker completion compares the lease, original digest, state and policy. A synthetic image checks the detector chain on startup, hourly when healthy and more frequently after failure. The report console distinguishes disabled, offline, error, stalled and running states and shows the pending count. The application monitors the heartbeat independently. Keep the worker and MongoDB health under deployment monitoring.

The worker reconciles abandoned drafts after a day and eventually removes bytes when the parent was erased, both parties deleted the message, or an edit removed the attachment. Relevant evidence from an actual report is retained for 30 days. Report evidence is available only in the assigned inquiry, with private communications permission for private material. Evidence is concealed until opened. The owner can request review of a general image-policy block. Approved review leaves the draft under the owner's control. Existing moderator restrictions, warnings and appeals apply.

## Verification

The server workflow starts a single-node MongoDB replica set and a dedicated Redis instance. After staging the website, it runs the authenticated HTTP regression with disposable users and its own temporary database. To reproduce it locally, install the scanner test dependencies and point the script at dedicated loopback services. The Java executable is configurable with `--java`.

```sh
python tools/attachment_scanner/tests/publication_http.py --mongo-port 27291 --redis-port 26402
```

The regression records ordinary send latency and exercises authorization, retries, concurrent edits, forwards, both Kid directions, forum publication and exact reports. Its document fixture uses a test antivirus result. Production validation also needs the maintained malware service, OpenAI project, moderator workflow, and target web and native releases.

## Text decisions and references

Ordinary text uses the shared local rule plus existing permissions and rate limits. Examples that pass include “Good game”, “好棋” and “Ván cờ hay”. A link to the confirmed blocked chess-bot.com destination is rejected in each language. The actionable prompt is “Remove the blocked link and try sending again”, “请移除被拦截的链接后重新发送” or “Hãy bỏ liên kết bị chặn rồi gửi lại.” Edits retain the last accepted content on rejection.

The desktop reference uses the picker callback to stage files, renders previews or generic file rows, and binds removal and clearing separately from submission. LiXiangQi uses its own theme and composer.
