# Challenge and matchmaking variant audit

## How the invitation was sent

A two-day Mini Xiangqi rematch copied its predecessor's Mini rules but omitted its native board. The inherited `chess.variant.Standard` field describes a normal start for several different boards. The challenge constructor supplied Xiangqi as its missing native board and accepted the combination. The challenge service could then store the invitation and notify its recipient. The joiner rejected it when it tried to build the game. The browser redirected to the invitation without showing the rejection.

New challenges require the native board and resolved rules. The constructor checks the pair and the starting position before an invitation reaches storage or notifications. Played two-player games also check the pair at creation. Existing invitations can still be read and canceled.

| -------------------------- | -------------- | ---------------------------- | -------------------------------------------- |
| Standard Xiangqi           | Tiantian       | Unrestricted                 | Standard board                               |
| Jieqi                      | Jieqi          | None                         | Fresh private deal required                  |
| Mini Xiangqi               | Mini Xiangqi   | None                         | Mini board                                   |
| Manchu+                    | Manchu         | None                         | Manchu board                                 |
| Game of the Three Kingdoms | Three Kingdoms | None                         | Separate three-seat game and challenge model |

Two-player public lobby offers use their board's default rules. Ranked live invitations also require the variant's ranked clock and eligible members. Public Three Kingdoms correspondence offers wait for all seats. The rated Three Kingdoms room has its own matchmaking service.

A separate constructor test lists the allowed pairs explicitly, checks positions from other boards and exercises the played-game guard. Browser checks use disposable local players and games. The reported production invitation requires no migration.
